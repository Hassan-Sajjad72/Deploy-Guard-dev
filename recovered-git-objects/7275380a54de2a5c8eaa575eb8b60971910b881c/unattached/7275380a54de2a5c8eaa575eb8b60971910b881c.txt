  owned projects; cross-workspace project and environment requests returned
  `403`. One stored secret was encrypted at rest, returned only as a mask, and
  neither plaintext nor ciphertext appeared in HTTP responses.
- Stack detection passed clean Express and Python cases plus the explicit
  configuration-required safety cases. The serializable planner proved eight
  concurrent identical requests create one intent, unchanged source is
  `no_op`, changed source is `release_only`, and a second project proceeds
  independently. Real PostgreSQL advisory-lock and BullMQ duplicate/restart
  delivery checks passed.
- The managed first-release supervised fixture completed one exact job through
  real disposable PostgreSQL/Redis and an independent non-cloud worker. It
  truthfully withheld a stable URL because no provider deployment was executed.
- The final browser demo used one canonical Overview Deploy command. It created
  one durable operation, published and consumed one deterministic BullMQ job,
  rendered Analyze/Build/Prepare/Deploy/Verify and Live, and restored the same
  stable/latest state across Overview, Deployments, Dashboard and Plan & Usage
  after refresh. It left one provenance row, three succeeded effects, and zero
  live leases, owners or claims. Evidence: [local FYP demo](docs/architecture/two-lane-migration/evidence/fyp-local-demo/latest.md).
- The shared Compose release worker was gracefully restarted only after queues
  showed zero waiting/active/delayed work and PostgreSQL showed zero live
  leases/owners/claims. It returned to `NORMAL_V1_RELEASE_CONSUMER_READY`; both
  infrastructure workers remained healthy.
- The developer terminology guard covers every routed developer page and the
  selected-project navigation. Plan & Usage no longer renders Terraform or raw
  v1 lifecycle wording. Ordinary navigation contains only the six project
  surfaces and no operator controls.
