## Shared normal-v1 platform blocker — resolved

The former Smart Retail UUID binding was a real P0 product blocker: a supported
project could pass detection and preflight yet receive
`NORMAL_RELEASE_LANE_STATUS_DISABLED`. Normal-v1 now has two explicit modes:

- `shared` is the reusable platform mode. Release, infrastructure-plan, and
  infrastructure-apply workers start with one `dev` environment policy and no
  project UUID list.
- `canary` remains an optional exact project/`dev` harness. Switching modes does
  not require a generated per-project Compose file.

Shared jobs carry immutable workspace, actor/role policy, project/environment,
intent, source/contract, manifest revision, AWS account/region, and resource
namespace evidence. The worker re-reads the project, owner, actor, deployment
contract, preflight, intent, and manifest revisions before ownership. Missing
shared evidence, changed workspace/project evidence, invalid authorization, or
account/region drift fails closed before handler invocation. Project/environment
advisory ownership, operation leases/fences, deterministic outbox/job IDs,
immutable manifests, and side-effect journals remain the isolation boundary.

The base `docker-compose.yml` is now the only ordinary worker composition. It
defines one shared service for each role. Infracost is available only to the plan
worker; Stripe, SNS, Trivy, fixture handlers, and all unrelated bypasses remain
disabled. `backend/.env` is ignored, mode `600`, and contains process-local
activation only.
