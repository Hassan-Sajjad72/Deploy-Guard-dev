## Iteration 7 completed result

- `/projects/:projectId/requirements` is the single Environment surface. The old
  `/env` URL redirects there. Required application inputs, managed database
  selection, and optional variables coexist without a second page or state
  source; stored secret values remain masked. Raw configuration ownership and
  fingerprint details were removed from the developer surface.
- Developer Logs now reads a closed `application-logs` projection. It contains
  only sanitized timestamp/message events and availability state. The legacy
  pipeline-run/event log page, live provider stream, and related client APIs and
  components were removed. Historical pipeline reads are admin-only.
- Developer Metrics now reads a closed `application-metrics` projection and
  exposes only CPU, memory, request latency, request rate, and a bounded time
  range. Provider selection, provider identity, labels, raw errors, and operator
  observability navigation are absent.
- Settings is application-focused: project identity, repository/branch,
  application directory, build/runtime commands, Environment, repository
  re-analysis, and archive. It no longer fetches detailed current state,
  detection/preflight reports, environment-key inventories, recovery state,
  cleanup controls, notification-provider settings, or raw detected runtime
  evidence.
- Logs and Metrics use the canonical current-state stable-release decision
  before requesting application evidence. Provider-shaped runtime/log/health
  endpoints remain available only to administrators; the new closed projections
  remain authenticated for admin, developer, and eligible readonly users.
