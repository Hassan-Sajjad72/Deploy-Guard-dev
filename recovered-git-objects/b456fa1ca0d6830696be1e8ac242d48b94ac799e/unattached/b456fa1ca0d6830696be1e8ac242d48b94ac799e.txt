Scope: Railway transformation through Iteration 6 — operator/admin segregation.

Stripe, or SNS.

## Iteration 6 completed result

- Activity Log, recovery, detailed detection/preflight, troubleshooting,
  security, cost, infrastructure, Terraform export/state, storage,
  orchestration, detailed runtime health, cloud resource inventory, destroy,
  and cleanup pages now exist only inside the frontend admin route boundary.
  Activity Log is absent from ordinary navigation and appears only in the admin
  section; operator modules remain invisible to non-admin users.
- Matching backend reads and mutations are guarded by the admin role. The
  focused metadata test proves admin acceptance and developer, readonly, and
  unauthenticated rejection across the detailed controller families. Canonical
  developer current state and Deploy/Approve Cost remain available, as does
  developer-owned re-analysis after changing source settings.
- Detailed detection and preflight links/reads are no longer requested by
  ordinary Project Settings. Administrators retain those diagnostics; developers
  retain only the re-analysis command and sanitized current-state outcome.
- Twelve unused legacy/internal frontend API exports were removed, including
  stage recovery, direct release-lane prepare/dispatch, Terraform approval, and
  legacy pipeline start/cancel/retry calls. Nine unrouted compatibility/control
  components were removed, including legacy start/current-action, raw recovery,
  Terraform planning-detail, and redundant role-wrapper components.
- `test:automation` no longer invokes `PipelineService.startRun()`, cancellation,
  or legacy Terraform approval. It is now a retirement guard covering ten
  authenticated legacy endpoints: each returns HTTP 410 code
  `LEGACY_DEPLOYMENT_EXECUTION_RETIRED` before touching an execution dependency,
  creating a run, or publishing queue work.
