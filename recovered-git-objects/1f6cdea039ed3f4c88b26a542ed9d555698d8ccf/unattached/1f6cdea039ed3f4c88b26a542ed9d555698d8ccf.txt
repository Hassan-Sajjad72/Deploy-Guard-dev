# DeployGuard Verified Result

Date: 2026-08-01  
Scope: Railway transformation through Iteration 1 developer/operator exposure
audit. No application source change, deployment publication, or AWS mutation was
authorized in Iteration 1.

## Verdict

**NO-GO — the protected shared normal-v1 engine is locally healthy, but the
Railway-like developer product contract is not yet implemented end to end.**

Shared-worker readiness remains a verified foundation, not a launch verdict. The
completed exposure audit proves that current developer pages and APIs expose
internal Terraform approval/details and that the canonical response does not yet
implement the required sanitized `developerState`/`developerAction` contract.

## Iteration 1 exposure evidence

- Audited 37 frontend routes, all 35 page modules, routed child components, 135
  frontend API exports, their Nest controller boundaries, and service-level
  project authorization.
- Classified every route/page and meaningful action as developer,
  operator/admin, deprecated, unsupported, or mixed.
- Extracted and classified all 97 top-level fields returned by
  `ProjectCurrentStateService.getCurrentState()`: 15 contain potentially usable
  developer facts only after projection, 26 are compatibility fields to replace,
  and 56 are operator/admin evidence.
- Enumerated every developer-accessible code-bearing surface: release safe codes,
  lifecycle/history codes, operation evidence/event/log codes, activation code,
  recovery/diagnostic/failure codes, workspace-history lifecycle code, and legacy
  endpoint codes.
- Confirmed that `ProjectDetails` and `ProjectPipeline` directly ask developers to
  approve Terraform apply and call the exact infrastructure-apply dispatch.
- Confirmed that Deployments falls back to legacy `ProjectPipelineRun` history
  when no normal-v1 operation is projected, and the selected Logs route is legacy
  pipeline events rather than application logs.
- Confirmed that the raw 97-field current-state and release-lane status are
  available to developer/eligible readonly roles. Detailed recovery, cloud,
  Terraform, identity, modes, and code fields therefore require backend—not only
  navigation—separation.
- Confirmed that legacy mutation endpoints for automation, pipeline, infrastructure
  and orchestration return `LEGACY_DEPLOYMENT_EXECUTION_RETIRED`; their remaining
  frontend exports/read compatibility do not restore a legacy execution path.
