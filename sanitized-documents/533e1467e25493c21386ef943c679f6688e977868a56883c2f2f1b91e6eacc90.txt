    13 targeted applications: 5 Python + 5 JavaScript/TypeScript + 3 other languages



• Purpose: a smaller, higher-value deployment matrix for the real AWS test campaign.
• Primary coverage: FastAPI, Flask, Django, Fastify, Express, NestJS, Go/Gin, Laravel/PHP, and Spring
Boot/Java.
• ENV rule: only high-confidence values from inspected repository configuration are included. If the source
evidence is weak or inconsistent, it is not included.
• Platform rule: DeployGuard owns PORT=8080 and HOST=0.0.0.0. Proposed ENV blocks intentionally avoid
user-owned PORT/HOST unless shown only as platform-injected comments.
• Secrets are test-only placeholders/random values. Never reuse them for production.

Test strategy
Python set: Five applications cover FastAPI, Flask and Django, with SQLite/no-DB cases plus a managed PostgreSQL
case.

JavaScript/TypeScript set: Five applications cover Fastify, Express and NestJS, including both SQLite and managed
PostgreSQL paths.

Other-language set: Go/Gin, PHP/Laravel and Java/Spring Boot verify that the deployment path is not accidentally
optimized only for Python/Node.

ENV discipline: Paste only the proposed test ENV. Do not copy every variable from a repository template when it is
optional or unrelated to boot.

PORT discipline: Do not repair a failed app by changing DeployGuard platform port. A repository that does not obey the
runtime contract should produce a clean failure that you record.

Recommended execution order
Run SQLite/no-database applications first, then PostgreSQL applications, then the cross-language controls. After basic
deployment passes, reuse one successful app for redeploy -> rollback -> destroy lifecycle proof.

Evidence to capture for each deployment
   Exact repository + branch + source SHA selected by DeployGuard.
   Railpack build succeeds or returns a clear build failure with logs.
   Application runtime probe receives platform PORT=8080 and HOST=0.0.0.0.
   Image is published only after runtime validation passes.
   Immutable ECR digest is recorded and the exact digest is used by ECS.
   Unknown user ENV values remain unchanged; platform-owned PORT/HOST win over user input.
   For PostgreSQL cases, stale local DB aliases are replaced with managed runtime values and secrets are not exposed
    in logs.
   ECS reaches RUNNING, ALB target becomes healthy, and the public endpoint returns an application response.

One full lifecycle after compatibility testing
After several applications pass basic deploy, choose one stable low-friction app and prove: Deploy -> new commit
Redeploy -> Rollback to previous immutable digest without rebuild -> Destroy -> verify AWS cleanup.
