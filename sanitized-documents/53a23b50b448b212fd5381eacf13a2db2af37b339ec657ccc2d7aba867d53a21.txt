                   DeployGuard Public Repository
                      Deployment Test Matrix
30 GitHub applications with inspected ENV templates and conservative smoke-test ENV
                                        files



• Purpose: give DeployGuard a broad public-repository deployment test set without guessing ENV names.
• ENV confidence: HIGH for every included repository - the repository ENV template was inspected.
• Deployability: intentionally NOT pre-certified. A build/runtime failure is part of the platform test.
• Platform rule: do not paste PORT or HOST from source templates. DeployGuard owns PORT=8080 and
HOST=0.0.0.0.
• Secrets below are randomly generated TEST-ONLY values. Generate new secrets for any real deployment.

                        DeployGuard - Public Repository Deployment Test Matrix | Test-only configuration
How to use this matrix
1. Start with Tier A: These use SQLite, local files, or no database and are the fastest way to validate source checkout ->
Railpack build -> runtime probe -> ECR -> ECS/ALB.

2. Then run Tier B: Select DeployGuard managed PostgreSQL. The proposed ENV deliberately includes normal database
aliases so the managed database replacement path is exercised.

3. Finish with Tier C: Use managed MySQL or MongoDB and verify the bounded database alias replacement reaches the
application at runtime.

4. Treat PORT failures as real evidence: I intentionally removed PORT/HOST from every proposed ENV. If a repository
ignores DeployGuard PORT=8080, the runtime probe should reject it. Do not “fix” the test ENV by adding a different app
port.

5. ENV scope: Only variables that are strongly supported by the inspected template are included. Optional paid API keys
are blank or omitted when the repository can boot without them.

Recommended test sequence
Run the low-friction entries first, then PostgreSQL, then MySQL/MongoDB. Within a tier, the numbering is only a
convenient reference, not a quality ranking.

Deployment evidence to capture for every repository
   Exact source SHA checked out.
   Railpack version and build result.
   Runtime probe receives platform PORT=8080 and HOST=0.0.0.0.
   If the probe fails, preserve the application logs and classify the failure rather than changing the platform port.
   Image is pushed only after runtime validation and an immutable ECR digest is recorded.
   Exact digest is used by ECS.
   For managed databases, verify stale/local database aliases are replaced by runtime-managed values and secrets are
    injected through secret references.
   ALB target becomes healthy and the public endpoint returns a real application response.
   Redeploy a new commit, rollback to the previous digest without rebuilding, then destroy and verify cleanup.



Important: This matrix validates the ENV selection with high confidence; it does not guarantee that every public repository
obeys DeployGuard’s runtime contract. That is exactly what the deployment campaign is intended to discover.
